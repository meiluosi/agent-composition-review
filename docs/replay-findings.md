# v4 复盘：执行能力补齐，指令增益未证实

48 次计划运行全部有效，未选择性补跑。三组配置在每次 57 个输入的实际验收上均为 16/16 通过，并均达到最小配置改动数。原始配置判定也均为 16/16 正确，两个正常任务各两次的额外改动均为 0/4。完整数据见 [实验报告](../evals/iterations/replay-2026-09-30/REPORT.md)。

## 本轮确实补上的部分

此前 v3 的证据检查器主要检查 ID 引用和状态枚举，无法验证真实状态转换。v4 增加动作/状态模型、组合义务、有限输入域生成与实际轨迹验收，已在本地流水线中执行。六种缺陷的 336 条工具回归、48 份模型配置的独立行为验收、可单独解压运行的包，分别提供不同层次的证据。

另外，当前主包移至 `skills/agent-composition-review/`；候选、维护脚本、文档、评测分开。主包原有五个运行文件内容保持不变。组织方式更清楚，但没有证据证明原目录导致效果下降。

## 为什么仍然不能说 Skill 有提升

本轮 **A 是“无额外 Skill 指导 + 共同工具”，不是“没有契约、没有执行工具”**。三组都拿到结构模型、实现代码、回放工具和直接要求实际验证的共同提示。模型都能利用这些材料完成只有六个离散配置选项的任务。

三组各 16/16 次调用了回放工具，各合计 28 次；工具内部实际执行 generate/check。v4 的执行参考文件被读取 16/16 次，但没有模型直接调用额外结构命令。由此只能看到，在任务已经提供结构和执行入口时，新增文字没有带来本次可测的收益；无法分离工具自身、建模方法和指令的效应。

v4 输入 token 1,127,561，比 A 的 878,508 多 28.3%；比 v3 的 1,148,308 少 1.8%。输出 token 分别为 A 5,740、v3 6,478、v4 5,906。墙钟中位数 49.9 / 50.5 / 51.4 秒，包含调用与工具耗时，不是纯模型服务延迟。一条 v4 运行耗时约 254 秒但仍有效完成；不能将单次慢请求归因为 Skill。

任务配对差值区间 [0,0] 来自全部相同的开发得分，存在明显天花板。八个任务仍是同一个自建系统的变体；57 个验收输入也不是 57 个独立真实任务。这些结果不能与先前外部归因题拼成“效果从 41.7% 提高到 100%”的曲线。

## 版本决定与下一轮依据

**v4 保留为可运行候选，不替换默认主包和个人安装。** 本轮没有发现配置修复退化，也没有取得提升证据。默认包内容仍保持原样不是宣称旧版更优，而是保留可复核的版本边界。新执行模块可以显式试用。

下一轮最值得测的是尚未覆盖的工作，而不是继续加长理论清单：

1. 从原始需求、代码和轨迹自行建立结构，发现漏掉的语义条件；本轮直接提供了模型。
2. 使用不同真实系统的修改任务，检验任意代码修复及行为保持；本轮是有限配置选择。
3. 比较基本工具、加入契约/回放工具、再加入 Skill 指导，分开测工具与指令的增量；本轮仅测最后一项。
4. 自然触发、模糊目标、并发状态和未声明全局约束分别建立新判据；不要把它们算作本轮已验证能力。

这些是未来独立实验的设计依据，本轮不继续消耗额度追加结果导向的任务，也不把已看过的答案改名为保留集。
