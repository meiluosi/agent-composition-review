# 模型与指导交互：有限开发筛查

此方案须在正式调用前连同任务、判据、工具、指导、执行器和分析代码冻结。没有正式结果时完成预检查；冻结后的错误另外披露，不能修改历史评分器来提高成绩。

## 问题与适用范围

检验三个问题：当前 v4 指导是否改善较低成本模型的业务交付；是否超过朴素工程清单；这个增量是否与 Astra 不同。实验识别固定共同工具之上的指导包效应，不分离某条范畴论定理、工具本身或目录组织的因果作用。指导长度和内容不同，不能宣称控制了长度。

模型预先选择 `gpt-6-astra/high` 与 `gpt-6-luna/high`。官方模型页面将 Luna 定位为高效率/低成本模型，本机模型目录也列出二者；通过现有 Codex 登录调用。先对每个模型做一次独立、无正式题目的工具连通性检查。若不支持或服务失败，停止并记录，不能按成绩改选另一个模型。请求模型名与精确后端快照不同；后者不可见。相同 high 设置不代表相同推理算力。Luna 是否在这些任务上较弱，由基线结果判断。

四个新编写的开发家族：租约任务队列、检索结果缓存、分块工具事件流、工具结果合并。每家族三个变体：组合相关故障、正常实现、节点内部故障，共 12 题。这些是标准库可执行的自建任务；不是生产事故、外部专业基准或独立保留集。它们使用已知工程概念，但尚未参与本轮模型结果调优。正常参考经另一位代理审查和额外反例检查后冻结；仍不声称穷尽所有输入。

## 条件、提示与隔离

- A_tools：业务要求、原始实现、公开 smoke、Python 和两份可选结构/证据脚本及中立接口说明。
- B_checklist：A 加一份简短普通工程清单。
- C_skill：A 加原样的 v4 Skill 入口和按需参考、通用检索模板；脚本与 A/B 字节相同。

共同提示只规定业务交付与简短最终记录，不要求生成 model.json、列出不变量或采用某种推理流程。所有组可自由新增本地测试与记录。业务要求在同一家族三个变体中相同，不标注变体、故障位置或参考答案。

这是明确加载指导的效果试验，不是自动触发/技能发现评测。所有组禁止宿主 Skill 发现、插件、网络检索和多 Agent。交付必须自包含，唯一可编辑的原始业务文件为 app.py；不得改任务、smoke、工具或参考。模型退出后，在独立临时目录与进程执行隐藏验收；不得把失败验收反馈给该次执行者。shell/Python 可读取标准库，这不是恶意执行者的完整读隔离证明。命令记录作事后违规审查。

## 调用上限与失败规则

12 题 × 2 模型 × 3 条件 × 2 重复 = **最多 144 次正式尝试**。另有每模型一次独立工具 canary（共 2 次），不参与效果统计。不运行模型裁判，不为回答错误、无效格式或超时重试。各次新临时目录、新进程/ephemeral 会话，固定 CLI 版本；先写开始记录再调用。随机种子固定交错顺序，不控制模型采样随机性。

单次 360 秒，上下文和推理用量由服务记录，三路并发；同一模型的三条件使用相同设置。首批最多 6 次供执行完整性检查，不按效果修改素材；之后续跑原计划。若额度、鉴权、传输或服务错误，立即停止新增调度，收完已在运行的调用；保留所有失败，未开始项标 pending。不能用缺失结果判断能力。任务超时计为失败，单列报告；如果超时系统性偏向某模型，这是该时间预算下的结果，不能单独归因为指导。

## 指标与分析

首指标：有效完成且全部隐藏业务验收通过的比例。另列最终源码行为通过率，以区分执行/格式和业务失败。有效完成须满足退出、最终格式、工作区保护等条件。无效、超时等已尝试项计入已尝试分母；完整计划分母、pending 与基础设施失败另列，不能把未运行当作模型答错。跨条件差值同时报告全部已尝试和六单元完整配对集合；运行不完整时不作升级决定。

正常对照单独报告行为回归、原实现误报（violation）及不确定（insufficient）、缺失结论、源码是否变更；源码变更本身不是错误。缺失源码或基础设施失败时，正常行为记为无法评价，不归因为业务回归。节点内部与组合缺陷修复分别报告。主指标不是 JSON 或措辞匹配，也不以报告长度/术语打分。

先对每题两次取平均，再对家族等权。四个家族内的题和重复相关，不能把 144 次或验收断言当作独立样本。报告每家族、每题数据；四家族的 256 种有放回重采样分布仅用于敏感性展示，不作为可靠总体置信区间。全部满分时区间退化不能证明差异为零。

预先比较：各模型 C−A、C−B、B−A，以及交互 `(Luna C−A)−(Astra C−A)`。不因看到结果再挑选子集、模型或指标；比较探索性，无多重比较显著性主张。正交互仅表示这两个指定配置上的观测，不证明模型规模规律。

分别累计 input/cached input/output tokens，记录用量缺失、时间和工具调用。缓存输入是总输入的一部分，不重复相加。不将 token 或墙钟直接当实际收费。官方 API 单价仅是选型背景；Codex 订阅额度没有可核验单次货币账单，不宣称实际省钱或按 API 报价伪造费用。同质量下的效率只作为后续产品假说。

## 预先决策门槛

144 次全部有可解释结果且无基础设施/隔离问题，才应用以下开发筛查规则。它们是投入筛选，不是统计显著性：

1. 对某模型，C−A 至少 +12.5 个百分点（24 次中净增加 3 次），C−B 至少 +8.3 个百分点（净增加 2 次），C−A 在至少两个家族为正，而且正常行为回归、行为无法评价（含源码缺失）、误报、不确定及缺失结论均不劣于 A 与 B，才将当前 Skill 标记为“值得另行冻结保留集确认”。仍不升级默认版本、不宣传稳定增益。
2. 若 B 通过同样的对 A 收益/跨家族/正常保护门槛，而 C 未显示额外实用优势，优先进入简短清单方向的后续验证。不能仅凭不显著就声称两者等效。
3. 若两模型基线均接近满分（≥22/24），结束本轮并记录验收饱和；不得继续追加更难题到本轮或宣称 Skill 无效。
4. 无条件达到门槛，结束当前版本的追加调用；保留理论资料和可执行案例，但不继续靠增加理论说明推进本版本。区间宽或样本少时结论为证据不足，而非证明没有任何收益。

本目标到完成有限筛查、作出上述决定和发布可复核结果为止。若出现信号，保留集需要独立新方案与新任务，不能把本轮已见任务改名为保留集，也不自动超出 144 次上限。
