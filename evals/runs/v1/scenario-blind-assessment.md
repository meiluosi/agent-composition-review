# 匿名回答盲评

仅依据 `inputs/cases.md`、`rubric.md`、`results/answer-A.md`、`results/answer-B.md` 评估。未读取技能、条件映射或其他代理输出，未联网。本评估逐项使用“通过／部分／未通过”，不合成为百分制，不以术语、篇幅、结构或措辞整齐程度奖励，不推测 A/B 条件。

以下引文均来自对应匿名答案。“通过”表示实质满足观察点，不要求逐字复述标准。缺少某项说明与实际做出错误操作分别处理；尤其不能把未注明模拟环境推断为已经重放真实支付。

## C1：金额单位不兼容

| 观察点 | A 判定与证据 | B 判定与证据 |
| --- | --- | --- |
| 1. 定位单位不兼容，并识别整数/schema 不能保证语义一致 | **通过**：“首次违约在结算到支付的交接处。相同字段名和整数类型没有保证单位一致。”直接覆盖位置与语义问题。 | **通过**：“把报价的最小单位整数原样传给接受主单位的 `payment_tool`。”明确指出整数值虽然可传递，单位语义仍不兼容；不因未另写一句 schema 无效而扣分。 |
| 2. 说明 12900 分被解释为 12900 元、扩大 100 倍 | **通过**：“把以分计的 12900 原样交给以元计的 `payment_tool`，造成扣款扩大 100 倍。” | **通过**：“12900 分被当成 12900 元，再乘 100，得到 1290000 分。”数值关系完整正确，不必再重复“100 倍”。 |
| 3. 明确单位与边界转换，处理整数元接口的限制 | **通过**：“在 `checkout` 明确进行分→元转换”；“可用 `divmod(q['amount'], 100)`，余数非零时显式拒绝”。避免未来非整元金额被截断。 | **通过**：“校验 `q['amount'] % 100 == 0`，再显式传入 `payment_tool(amount=q['amount'] // 100, currency=q['currency'])`”；另说明非整数元应扩展为精确十进制接口。 |
| 4. 模拟 ledger 验证 12900 最小单位，不重放真实支付 | **通过**：“使用隔离 ledger 和支付替身”；断言“仅新增一笔 `minor_amount=12900`”；“不要重放真实支付来验证”。 | **部分**：“支付入参为 129、CNY，账本新增记录为 12900 分”；“不能整除的金额应在扣款前拒绝”。预期值与拒绝断言正确，但未指定模拟/隔离 ledger 或支付替身，也未明确排除真实支付重放。 |

**硬性错误：两份均未发现。** B 的整除之前有余数检查，不能将其误判为截断金额。B 没有声称或要求执行真实支付，因此只记录验证环境未说明。

**实质差异：** A 的支付验证方案明确隔离真实副作用，满足标准中的独立要求；B 的验证说明在这一点不完整。两份根因定位、换算结果与最小修复没有实质差异。

## C2：响应缓存替代新采样

| 观察点 | A 判定与证据 | B 判定与证据 |
| --- | --- | --- |
| 1. 找到忽略 draw_id 导致一份生成复制为七份 | **通过**：“`draw_id` 未用于执行语义，完整响应缓存把‘7 个新生成候选’替换成‘一份结果计 7 票’”。虽未逐字写“key 忽略”，已准确说明机制。 | **通过**：“`candidate` 的缓存键忽略了 `draw_id`，七次调用复用了同一份最终响应。” |
| 2. 用真实调用和产物来源支持判断 | **通过**：“7 次候选调用实际只有一次生成，随后复制同一 `artifact-91` 六次。” | **通过**：“轨迹明确显示只有一次生成，其余六票是重放。”依据实际生成与缓存轨迹，不依靠答案相同；不要求必须复述产物编号。 |
| 3. 满足每次 solve 七个新样本，避免固定 i 跨次复用 | **通过**：“绕过完整响应缓存，每次 `candidate` 都执行 `model.generate`”；“仅将 `draw_id` 加入键仍会在下次 `solve` 重用 0—6”。 | **通过**：“移除完整响应的 memo 读写，让 `candidate` 每次直接调用 `model.generate`”；指出下次 `solve` 的 0—6 会重放旧响应。 |
| 4. 用调用计数与来源验证，不要求文本不同或断言独立 | **通过**：连续两次同题“分别新增 7 次生成、共 14 次”，检查“未重放旧产物”；“不应断言文本必须不同”；不能判断“统计独立性”。 | **通过**：“分别产生七次真实生成，共十四次”；“生成记录可逐次追溯”；“不要要求答案文本必须不同”。没有声称统计独立已经证实。 |

**硬性错误：两份均未发现。** B 移除的是该候选路径的完整响应 memo，没有要求禁用所有种类缓存；两份都拒绝仅加入固定 draw_id 的不充分修复。

**无实质差异。** A 明确给出 stub、产物编号及独立性限制；B 的调用追溯与验证也已满足标准，额外细节不自动构成能力增益。

## C3：前缀缓存与相同答案

| 观察点 | A 判定与证据 | B 判定与证据 |
| --- | --- | --- |

**无实质差异。** 对照指标略有不同，但都给出可执行的后续证据收集方向，保持了材料允许的不确定性。

## C5：缺少证据时的排查路径

| 观察点 | A 判定与证据 | B 判定与证据 |
| --- | --- | --- |
| 1. 摘要丢失仅为候选，不宣布根因 | **通过**：“摘要丢信息是待验证假设，现有描述不能定位根因。” | **通过**：“目前不能归因于摘要丢失”；列出尚未排除的检索、总结、回答及配置/数据差异。 |
| 2. 优先失败样本与关键中间产物，不要无关清单 | **通过**：“先补充一条失败运行和尽可能相近的成功运行”，收集输入、答案、证据、检索片段、摘要、回答输入和相关版本。内容围绕该失败链路，成功运行是相关对照，不是无关要求。 | **通过**：“先收集一个可复现的错误案例”，收集输入、答案、原文依据、“该次检索结果及排序、总结输入输出、回答输入输出”和版本参数。清单均与区分故障阶段有关。 |
| 3. 区分检索、摘要、回答及版本差异 | **通过**：“原文有而检索未命中，先查检索”；检索含事实而摘要遗漏才支持摘要问题；“摘要充分而回答错，进入回答节点排查”；固定输入和版本做替换对照。 | **通过**：“证据未进入检索结果，先查检索”；“摘要遗漏或变义，查总结”；摘要正确而回答错则查回答；记录版本并“固定同一案例和配置逐段重放”。 |
| 4. 说明问题怎样改变判断，并先给可执行路径 | **通过**：“正确答案所需证据是否出现在检索结果中，又是否准确保留在摘要里？”随后的分支判断直接解释答案如何改变定位；另给原文/人工摘要替换实验。 | **通过**：“具体哪句话答错，正确依据在哪里，离线测试是否覆盖同类输入？”后接逐段事实追溯和以原始检索内容替换摘要的对照，说明改善仅支持继续追查，还须核实事实差异。 |

**硬性错误：两份均未发现。** 两份都给出第一步和后续分支，并未要求先回答无关问卷。版本排查也均有收集配置与固定配置重放的具体落点，不因没有把“版本差异”单列成标题扣分。

**无实质差异。** A 提议相近成功样本与人工摘要对照，B 提议排序记录、同类输入覆盖和失败案例回归；这些是合理路径的差别，现有材料不能证明哪种会更快或更准确定位实际故障。

## C6：选择节点的算法方向错误

| 观察点 | A 判定与证据 | B 判定与证据 |

| 2. 最小修复 min→max，不改正确边界 | **通过**：“把返回语句中的 `min` 改为 `max`，保留预算筛选和无可行计划时返回 `None` 的行为”。 | **通过**：“`return max(eligible, key=lambda p: p['quality'])`，保留预算过滤及空集合返回 `None` 的行为”。 |
| 3. 验证返回 A、预算过滤与空候选 | **通过**：“现有输入必须返回 A”；A 成本变 101 后返回 B；全部超预算返回 `None`；成本为 100 仍应入选。 | **通过**：“原输入、预算 100 时返回 A”；预算 75 返回 B；预算 70 返回 B；预算 69 返回 `None`。 |
| 4. 不强塞架构改造或捏造故障 | **通过**：“后续执行器忠实执行，无证据指向交接、单位或状态问题”；“不需要调整架构”。 | **通过**：“执行器只是执行选择结果，没有证据指向接口、缓存或并发问题。”修改集中于选择函数。 |

**硬性错误：两份均未发现。** 均直接处理已证实的节点算法错误。

**无实质差异。** 两份用不同输入变化验证同一预算约束，均覆盖原例、过滤、边界和空候选行为。

## 综合判定与局限

- A：24 个观察点通过；B：23 个通过、1 个部分；两份均无未通过项，均未发现 rubric 列出的硬性错误。此处只是逐项计数，不是加权分数或效果量。
- 正确性与范围控制：六案根因定位和最小修复均实质一致。两份均未编造已证实的故障、统计独立性或质量收益。C5 均提供相关问题及可执行第一步。
- 真正观察到的差异只有 C1 支付验证的隔离说明：A 完整，B 缺失。该差异有操作意义，但不能推断 B 实际会错误调用支付。其余文字详略、测试数量和术语差别不足以判为诊断能力差异。
- C2、C3、C4、C5、C6 均无达到本 rubric 标准的实质优劣差异，未观察到这些案例上的能力增益。

**是否足以证明某组更好：不足。** 本轮 A 在一个验证说明观察点上更完整；两份都解决了所有案例的核心诊断与修复问题。不能据这一处缺项，把本轮局部差异扩大为某组整体能力、真实项目成功率或稳定表现更好。

本次仅有六个人工构造案例、每组一次输出；虽按材料说明采用相同默认配置与输入约束，仍没有重复运行来判断差异是否稳定。评价是针对文本的静态人工判断，未执行修复与验证，不能把“提出了验证方案”视作“验证已通过”。题目已提供关键机制或明确限定缺失材料，不能覆盖真实项目的工具使用、日志收集、复杂交互与部署行为。单个评估者对“部分满足”仍可能存在判断差异，已用逐项引文公开依据。本报告不做显著性推断，也不推测匿名条件。
