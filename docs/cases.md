# 案例说明与证据等级

本项目目前覆盖三个可执行案例和六个文本场景。可执行复现使用固定依赖及真实框架运行，不使用真实支付、发送消息或模型 API。

## LG-6446：快照被解释为补丁

来源：[公开 issue](https://github.com/langchain-ai/langgraph/issues/6446)。原报告未给出 langgraph 精确版本，本地使用 1.0.3；原代码和确定性改写都曾复现相同异常。这里发布的是独立重写的便携回归实现。

子图虽只在叶节点写 s1/s2，完整状态输出仍携带旧 b。父图将它作为更新，与另一路的新 b 冲突。修复限定输出 schema，保留全部输入字段。验收覆盖原错误、变化输入、图复用、读取上下文、调用次数和两层并行。此前还有独立有/无 Skill 修复试用，两组均通过，没有证明相对提升。

代码：[test_subgraph_boundary.py](../evals/cases/test_subgraph_boundary.py)。

## LG-8754：读取产生存储变化

来源：[公开 issue](https://github.com/langchain-ai/langgraph/issues/8754)。报告者测试 checkpoint 4.2.0 的特定提交；本地在 3.0.1 上复现同类行为。不能将这一结果描述为精确重现其全部环境，或声称其他版本都受影响。

对不存在的线程调用 get_tuple 返回 None，却因为嵌套 defaultdict 索引创建了空记录。便携测试实际运行 20 次，原实现产生 20 个线程条目。GuardedSaver 用非插入式查询提前处理未知线程/命名空间；同步和异步未命中后全部存储保持不变，并回归已有记录、显式 checkpoint、过滤、limit、before 和后续写入。

这是维护者依据来源实现的复现与局部修复对照，还没有进行独立模型诊断试用。该子类仅针对固定版本、单进程顺序访问的实验；没有证明并发读写/删除、自定义 storage factory 或所有成功读取都绝不修改内部辅助索引，不作为生产修复发布。

代码：[test_checkpoint_reads.py](../evals/cases/test_checkpoint_reads.py)。

## DOC-INTERRUPT：恢复不是简单从下一行继续

来源：[官方中断文档](https://docs.langchain.com/oss/python/langgraph/interrupts)。这是按文档行为构造的例子，**不是历史事故或框架 bug 报告**。

工作流执行一个已获授权的准备操作，然后暂停等待复核。恢复会重跑节点前部，使准备操作再次执行。测试用本地列表记录效果，观察到同一操作写入两次；按逻辑操作身份去重后只写一次，同时另一新操作仍可执行。

内存去重只是测试替身，不提供跨进程、进程崩溃或分布式 exactly-once 保证。若操作需要事前批准，应把批准放在它之前；若必须在暂停前产生效果，应由实际执行方提供符合业务的幂等与恢复机制。

代码：[test_interrupt_effects.py](../evals/cases/test_interrupt_effects.py)。

## 后续优先补充

- 缓存、随机采样的真实 SDK 调用轨迹，包含合法缓存的相邻反例。
- 小的中间误差导致工具动作改变的业务案例，明确距离与业务损失。
- 检索/摘要丢失限定条件和证据来源的真实输入输出。
- 多智能体共享定义变化、接口版本错位与非局部约束。
- 非 LangGraph 框架及工具边界，减少当前样本对单一框架的偏重。

这些是待补覆盖方向，不计入当前测试成绩。每增加案例，先确定它属于旧失效家族的变体还是新的家族。
