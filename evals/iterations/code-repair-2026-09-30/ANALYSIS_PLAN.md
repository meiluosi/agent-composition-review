## 研究问题与边界

上一轮直接给出了结构和回放工具，仅有离散配置选择，三组全通过。本轮不给参考模型或参考修复，要求执行者从业务要求和实现自行建立最小结构，直接修改 `app.py` 并验证。

三个实际运行机制各有故障版和正常版，共六个任务：LangGraph 1.0.3 的并行子图、Python 3.12 sqlite3/SQLite 的事务边界、Python 3.12 asyncio 的子任务生命周期。它们是应用集成问题的本地可运行复现，不是三个生产系统，也不是三个第三方库缺陷。LangGraph 家族此前已见过，另外两个依据官方语义编写；全部属于开发集，不声称外部保留集。

## 条件与规模

- A：基本文件、代码编辑和本地 Python 工具；无 Skill、无契约检查脚本。
- B：A 加 v4 的确定性契约检查脚本及中立命令说明；无 Skill 指导或理论参考。
- C：B 加冻结的 v4 Skill 入口和按需参考。

全部得到相同原始代码、业务要求、一个公开 smoke、相同模型输出格式/结构格式及相同依赖。结构格式是共同交付要求，属于共同提示负担，不将本轮称为自然触发实验。不要将 A/B 差值解释为范畴论全部思想的效应，或把 C/B 差值单独解释为某条定理的效应。

6 任务 × 3 条件 × 2 次 = 36 次执行。另对每份结果进行一次独立上下文、隐藏组别的模型结构评审，共最多 36 次评审。总计划不超过 72 次模型调用。使用 gpt-6-astra/high、执行并发 3、单次上限 480 秒；结构评审 180 秒。失败计入分母，不按结果补跑。两个重复仅是探索性试验，不能支持稳定提升宣传。

## 指标

首指标：所有适用行为断言通过的运行比例，包括正常任务保留行为。分别报告故障修复和正常保留，所有计划运行计入分母；另报告未修改正常源文件的比例，避免把无害风格修改混同于功能退化。

建模分两层：确定性验证 JSON 结构、引用和实际代码行范围；独立模型评审三个预先固定的机制判据，标签 covered/contradicted/insufficient，必须引用模型片段、代码及验收证据。评审者看原代码、提交代码、模型、实际验收及判据，看不到条件名、Skill 指令、工具日志或成本。评审不是人工专家裁定或数学证明，不能代替执行首指标。维护者对 contradicted/insufficient 和代表性 covered 做回读，保留原评审及修订理由。

按三个运行机制聚类报告配对差值，先平均每个机制内的两个变体和重复。只有三个家族，区间极不稳定；保留逐任务结果，不将 36 次视为独立样本，不将程序断言数量称为模型样本量。固定 c01–c06 顺序展示累计结果，不与此前异质任务拼接。

另报告模型是否调用新增检查脚本、建模/测试产物、token 和时间，缺失费用记未知。任务调用和结构评审的 token 分列。
