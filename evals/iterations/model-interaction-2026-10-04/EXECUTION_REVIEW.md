## 运行中发现的 m08 正常标签错误

在 m08 trial 1 的六份记录完成后回读，Astra A（`2c2982447f7bea923d2c`）报告了被重复字段覆盖的非标准 JSON 常量。主维护代理与独立复核代理都在冻结正常参考上复现：

```python
EventStream().feed(b'{"event":NaN,"event":"done"}\n')
```

原实现返回 done 并进入 DONE；Infinity、-Infinity 也一样。但题面要求 malformed JSON 必须抛 StreamError、进入 FAILED。JSON 数字语法不允许这些常量，Python 默认解析器却接受它们；再经重复键折叠，非法值会消失。[RFC 8259 §6](https://www.rfc-editor.org/rfc/rfc8259#section-6) 与 [Python 3.12 文档](https://docs.python.org/3.12/library/json.html#infinite-and-nan-number-values)支持这一判断。

重复键本身是另一件事：RFC §4 建议名称唯一，但不强制解析器统一处理；题面没有明确重复键策略。Luna 三组涉及重复键的判断不能全部当作与非法常量相同的发现，也不能简单全部判为误报。Astra A 的上述反例则确实成立。Astra B/C 的 satisfied 也只代表它们通过了已执行检查。

因此，m08 的原正常标签及其误报计数不能按字面解释；原隐藏验收也漏了这个边界。主评分、输入、调度和全部历史记录保持冻结，继续完成既定有限对照，不把修订输入回灌给模型。不依据该轮正常保护门槛升级 Skill，也不通过事后删题或替换评分制造增益。反例和修订参考另存为事后开发材料，不充当独立保留集。

可执行补充见[事后反例](../../model_interaction_followup/README.md)。修订参考仅通过 `parse_constant` 拒绝非法常量，保留原重复键策略；5 项回归通过，并通过原 12 项冻结验收。它未被用于任何正式调用。
