# ACR005 · retry 与副作用叠加

**级别**：medium（静态检查；需要确认写操作确实非幂等）
**命令**：`acr scan <path>`

## 症状

- 节点失败后自动重试，用户收到两条消息、被扣两次款、生成两个订单。
- 恢复执行后，工具调用次数比预期多。
- 重试本身“成功”了，但外部副作用已经发生两次。

## 为什么发生

retry 的语义是**重新执行整段节点**。如果节点里包含非幂等外部写，第一次调用可能已经成功、只是在返回或记录状态时失败，重试就会再执行一次写。框架无法知道你的外部系统是否幂等。

## 最小修复

```python
def charge(state: State) -> dict:
    key = f"{state['order_id']}:charge"
    charges = state.get("charges", {})
    if key in charges:
        return {}  # 已执行：重试成为 no-op
    receipt = payment.charge(state["order_id"], idempotency_key=key)
    return {"charges": {**charges, key: receipt}}
```

若外部接口不支持幂等键，先在本地持久化“调用已发起/已完成”的记录；或者在重试前查询外部状态，确认是否已生效。

## 验证

- 模拟第一次调用成功但记录状态失败，重试后外部只发生一次。
- 幂等键在多次重试间保持不变。
- 关闭/降低 retry 后行为仍符合业务预期（不要把幂等性完全依赖在重试策略上）。

## 误报边界

- 写操作本身幂等（PUT/upsert/带唯一约束，或外部 API 支持幂等键）：风险低，可只记录。
- retry 只覆盖纯计算或只读校验阶段：无需修改。
- 已确认外部接口有服务端去重但 scan 看不到：按“设计如此”处理，补一条重试验证即可。
