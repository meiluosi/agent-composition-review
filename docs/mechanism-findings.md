# v3 机制评测复盘与版本决定

## 决定

保留模块化 v3 为可打包的开发候选，不替换主 Skill 或个人安装。72/72 次有效，无选择性重试。主指标三组全为 100%，没有观察到增量收益；六个短小、明确约束的开发家族出现明显天花板，不能据此证明能力相等或候选已适合复杂任务。[完整报告](../evals/iterations/mechanisms-2026-09-29/REPORT.md)

| 指标 | 无 Skill | v1 按需参考 | v3 按需参考 |
| --- | ---: | ---: | ---: |
| 成对契约判断 | 100% | 100% | 100% |
| 单例契约判断 | 24/24 | 24/24 | 24/24 |
| 离散命题严格匹配 | 71/72 | 70/72 | 72/72 |
| 指定位置及契约判断 | 20/24 | 22/24 | 20/24 |
| 正常例误报 | 0/10 | 0/10 | 0/10 |
| 输入 token | 519,767 | 960,368 | 848,565 |
| 读取参考的运行 | 0/24 | 23/24 | 22/24 |

v3 输入比 v1 少 11.6%，比无 Skill 多 63.3%。这是真实读取条件下的本次观测，不能归因到“拆模块”这一单独因素：入口、内容与读取选择同时变化。其墙钟中位数 46.3 秒也没有低于 v1 的 43.5 秒；时间受网络及并发影响，不能直接归为模型效率。

候选正文从 2,458 字符降至 1,411 字符，主体更短不等于总调用成本更低。22 次实际读取了至少一份参考，说明渐进披露能运行；读取行为本身不是诊断收益。

## 位置指标暴露了我们自己的目标歧义

以下复盘知道组别，属于开发分析。冻结标签和原始成绩保持不变，没有事后给候选加分。

**m01：违规动作与终态证据。** 标签选择 e5 的错误路径写入，三组两次都选择 e8 的最终交付缺失观察。解释均正确识别错误路径，也都保留了表头错误已恢复和复制计划未执行。共同协议一方面要求“实际产生违规行为的事件”，另一方面允许在询问产物时选择观察事件；而任务问的是“当前交付要求”。这个混合目标使单位置判据不够清晰。六次位置不匹配不能合理地解释为六次未理解故障。

**m07：采样阶段与聚合阶段。** 标签选择 e3 复用完整结果缓存；无 Skill 和 v3 都两次选择 e4 将复制品算作独立票。两处分别违反新采样要求和聚合语义，解释都包含完整链路。v1 选择 e3，从而比另外两组多命中两次；这不足以证明它在根因分析上更好。

下一版协议应分别请求 `violating_action_ids`、`observation_ids` 与必要时的 `causal_candidate_ids`，在用户明确只问某种位置时才投影到单答案。相应验收必须重新冻结并重跑基线，不能修改本轮评分器后替换历史结果。

## 命题指标也不能直接支持候选优越性

差异都出现在 m03：过滤代码仅在计划中、最终交付材料缺失。

- v1 的一次回答把“已有证据证明交付违规/合规”均判为 refuted，并在解释中明确最终交付未知。冻结标签是 unknown。这里存在元命题“有无证明”和对象命题“交付是否违规”的语义差别；这不是编造了成功或失败。
- 无 Skill 的一次回答把“该过滤若执行会删除 south”判为 unknown，理由直接引用共同协议中“反事实陈述需要实际证据”。这暴露了我们指令范围过宽：在输入和操作语义足够明确时，可以用静态推导支持条件命题；这与无法仅靠轨迹断定整次任务干预效果不同。
- v3 在本轮三项命题都匹配标签，属于有价值的观察，但只有一个案例、两次重复，且题面含上述歧义，不能宣称其证据推理稳定提高。

后续应区分 `observation`、`deduction` 和 `causal_intervention` 三种支持来源。无需强迫可由明确程序语义推出的结论都先实际运行，也不能把静态条件推导升级为已经发生的事实。本轮没有修改共同协议或候选。

## 哪些东西已经验证，哪些还没有

已经验证：候选结构与链接、独立打包、只读工具读取、按需参考、证据检查器列明的拒绝规则、案例标签不进入执行目录、重复及无效运行的统计分母。新增离线检查共 11 个测试方法；旧框架 10 项和原评测基础 12 项也通过。这些数量不是模型能力分数。

证据检查器能拒绝引用缺失与部分状态矛盾，但对结构合法的虚假观察无能为力；对应负能力边界有测试。模型本轮没有调用该检查器，因此不能把本轮命题成绩归因于程序约束。共同输出 schema 也给了三组同样的结构化支持，尚未单独识别中间记录的价值。

候选的 contracts、effects、evidence、probability-causality、gluing 五份参考有读取记录，quantitative 没有；定量重构模块未获得本轮模型行为验证。自动触发、独立新任务、长轨迹、节点内部错误、真实修复和干预回放仍未覆盖。

## 下一次实验应改变什么

优先修正诊断目标及证据来源的表示，再增加难度。使用一个可回放的小系统生成动作、观察和恢复的独立事件，包含多处违规和最终成功/失败；答案依据明确的目标或实际干预结果生成。保持无 Skill 对照获得相同工具与输出契约，单独比较附加记录/检查器的作用，避免把所有变化同时加入。

新材料与判据应独立于这 12 个开发例，并包含普通节点错误和无需 Skill 的任务。需要为新协议建立新基线；这不是马上扩大当前简单案例数量，也不是继续向入口堆叠理论段落。本轮到此完成候选实现、机制筛查、文档和可复核记录，下一轮尚未运行。
