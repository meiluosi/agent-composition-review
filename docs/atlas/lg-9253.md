# LG #9253 · retry 节点调用两个子图，第二个续用第一个的 checkpoint（ACR009，experimental）

**状态**：experimental（ACR009；exact 设计源，批次无新样本）
**一句话症状**：一个带 `RetryPolicy` 的节点先调用 `research`，在调用 `review` 之前抛错；重试耗尽后用 `invoke(None)` 恢复，结果打印 `RESEARCH` 而不是 `REVIEW`——第二个子图续用了第一个子图的 checkpoint。

规则检测的是“retry_policy + 一个节点内多个 subgraph invoke”的结构；checkpoint namespace 的实际复用是运行时行为，静态扫描不能断言。

## 最小修复

把一个节点拆成两个，让每个重试单元只负责一个子图：

```python
graph.add_node("research", research_node, retry_policy=RetryPolicy())
graph.add_node("review", review_node, retry_policy=RetryPolicy())
```

如果确实要在同一节点内调用多个子图，为每个子图传入独立的 checkpoint/namespace，并在恢复测试中断言“第二个子图真的执行了”，而不是只看最终文本。

## 验证边界

- **experimental**：#9253 是 ACR009 的 exact 设计源，但第二批 20 例中没有 `retry_policy + 2+ 子图` 样本，第三轮同样 `no_sample_found`；不能用同一案例既设计又验证。
- 第三轮明确记录 #9253（及修复 PR #9279）属已排除的旧案例，不能复用；因此没有独立 exact 命中。
- 仓库只做静态扫描；未在本地重跑重试/恢复序列来观察 namespace 复用。
- 新版 LangGraph 可能改变该命名空间行为；规则描述的是“这个结构有风险”，不是“所有版本都错”。
