# ACR008 · 缓存节点缺少稳定的 callable 身份

**级别**：medium（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 两个图各自跑都正常，共享同一个 cache 后，B 图返回了 A 图的结果。
- 节点第一次跑出 `"from graph A"`，换个 handler 再跑，还是 `"from graph A"`。
- 缓存命中率异常高，或者调用次数明显少于预期。

## 为什么发生

LangGraph 的节点缓存 key 需要包含“这个 callable 是谁”的身份（通常是 module + qualname）。如果节点传入的是：

- callable object（`HandlerA()`）；
- lambda；
- `functools.partial`；
- 从参数传进来的未解析 callable；

它可能没有可用的 module/qualname，cache key 的 namespace 退化成 `__dynamic__`。多个图共享同一个 cache 对象时，相同的节点名 + 相同输入就会互相命中，返回另一个图的结果。

## acr 输出示例

```text
$ acr scan app/graph.py
app/graph.py:40: medium ACR008
  Node 'process' enables cache_policy but its callable is not a statically named function...
  LangGraph's cache key may lack a stable function identity and collapse to a dynamic namespace...
  evidence:
    - node 'process' registered with cache_policy at line 40
    - callable could not be resolved to a module-level function (action kind: unknown)
    - graph compiled with cache=shared at line 39
  fix: Use a module-level named function for cached nodes, or include an explicit stable key/namespace...
  docs: docs/rules/ACR008.md
```

## 最小修复

优先用模块级命名函数：

```python
def process_a(state: S) -> dict:
    return {"out": "from graph A"}

graph.add_node("process", process_a, cache_policy=CachePolicy())
```

如果必须用 callable object，给缓存一个显式、稳定的命名空间/键，不要多个图共享同一个匿名 namespace：

```python
graph.add_node(
    "process",
    handler,
    cache_policy=CachePolicy(key=("graph-a", "process")),
)
```

## 误报边界

- 只有同时出现 `cache_policy` 与“无法解析为模块级命名函数”的 callable 才报；命名函数不报。
- **bound method 不报**：`self.method` / `instance.method` 有稳定的 module + qualname，不属于 `__dynamic__`。v0.5.1 起 scanner 会解析类方法；之前版本在这里有误报，真实公开代码见 [vanara bound method 案例](../atlas/lg-vanara-bound-method.md)。
- 静态分析看不到运行时 monkey-patch 或动态 `__qualname__`；如果项目自己保证 cache key 含稳定身份，可忽略。
- 共享 cache 本身不是问题；问题是没有稳定身份时还跨图共享。
- 规则命中不等于线上一定串结果；先看 cache key 实现与实际命中记录。

## 相关真实案例

- [langchain-ai/langgraph#8753](https://github.com/langchain-ai/langgraph/issues/8753)：callable object 的 cache namespace 退化为 `__dynamic__`，不同图共享 cache 时互相返回结果。
