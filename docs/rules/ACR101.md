# ACR101 · 重复工具调用

**级别**：medium（轨迹检查；重复发生的工具可能只是只读时降级）
**命令**：`acr trace <trace>`

## 症状

- 一条轨迹里同一个工具被调用了两次以上，参数几乎相同。
- 用户收到两条消息、被重复计费，或外部系统出现重复记录。
- 重试/恢复后的轨迹里出现“同一次业务操作”的第二份调用。

## 为什么发生

重试、流恢复、人工重放或节点重复执行都会再次进入调用工具的那一行。如果调用没有幂等键或去重标记，框架无法区分“重试同一次调用”和“用户真的要再调一次”。

## 最小修复

```python
def send_once(state: State, payload: dict) -> dict:
    key = f"{state['run_id']}:{payload['channel']}:{payload['user_id']}"
    sent = state.get("sent_keys", set())
    if key in sent:
        return {}  # 重复轨迹：不再调用
    deliver(payload, idempotency_key=key)
    return {"sent_keys": sent | {key}}
```

如果重复调用是**有意的重新采样**（例如同一问题多次生成），则应把 `sample_idx` 纳入调用参数与缓存键，并在报告中说明这是预期行为。

## 验证

- 重放同一轨迹，外部效果只发生一次。
- 不同业务操作（不同用户/消息）不会被误去重。
- 去重键持久化在状态或外部存储中，跨进程恢复仍有效。

## 误报边界

- 只读工具（搜索、读取文件）被重复调用：可能只是效率或循环控制问题，不一定是副作用故障。
- 采样/投票类调用重复是预期行为，需要看是否有 `sample_idx` 区分。
- 同一工具不同参数不算重复；正规化参数时不要忽略关键字段。
