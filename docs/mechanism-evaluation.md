# 成对机制评测的复现与边界

这是一项自建开发评测，目的是检查模块化候选是否能区分相邻条件，以及按需读取是否实际发生。它不属于 Who&When 或其他专业数据集，也不与前两轮曲线合并。

## 材料与运行隔离

- [案例与人工判据](../evals/mechanisms/cases.json)：六个家族，各两个变体；为了可复核，仓库文件包含 oracle，执行目录不包含它。
- [共同协议、输出结构与评分](../evals/mechanisms/core.py)：三组一致，已经提供证据与未知判断要求。结果反映 Skill 在该协议之上的增量效果。
- [候选](../evals/iterations/v3-candidate/SKILL.md)：一个入口和按需参考；主入口强制注入，不是自动触发实验。
- [冻结方案](../evals/iterations/mechanisms-2026-09-29/ANALYSIS_PLAN.md)、[manifest](../evals/iterations/mechanisms-2026-09-29/manifest.json)：输入、oracle、指令、评分、运行及分析程序均记录哈希。先冻结并本地提交，再启动运行；这不是第三方预注册服务。

runner 为每次调用创建临时目录，只写 `case["input"]` 和相应运行包。使用相同的 Codex 只读工具、相同模型与推理配置；禁用宿主 Skill 发现、插件、网络搜索和其他 Agent。临时目录在调用结束后删除。

只读沙箱不能保证宿主文件完全不可读。实验另审计可见工具命令，只认可明确的当前目录读取；未知命令语法按预登记规则标记为隔离未核实，不悄悄接受或补跑。这个审计也不能证明没有不可见的系统上下文，因此记录相关限制。

每次调用的启动标记、原始事件、最终输出和状态留在被 Git 忽略的 raw-runs 中。已启动但没有完成记录的任务不会被 runner 自动重试，以防选择性重采样。正常结束的已记录任务也不会重复运行。

## 可复核的指标

主指标按家族计算：两个相邻变体都答对所问契约 verdict，才算该次成对成功。两次重复先平均，再对六个家族等权。单例位置、命题、引用、误报和资源分开报告。

命题准确率是预设离散命题的严格标签匹配；它不检查回答全部自然语言。锚点覆盖是事先列定的事件 ID 是否被引用，不排除模型有其他合理证据。自动评分没有使用理论术语、篇幅或主观报告总分。

样本只有六个家族，且与候选一起设计。置信区间仅描述该小型开发集合；满分、退化区间或没有正常误报，均不证明在复杂真实任务上稳定有效。

## 命令

按仓库锁定版本安装 `requirements-benchmark.txt`。无需模型即可检查证据程序、输入隔离和统计分母：

```sh
python -m unittest evals.mechanisms.test_evidence evals.mechanisms.test_core evals.mechanisms.test_analysis -v
```

完成且公开评分后的图表可由 `python scripts/analyze_mechanisms.py publish` 重新生成，不调用模型。重新评测必须建立新的实验目录和协议；不要删除旧记录后用同一清单覆盖历史。runner 的 `run` 命令会使用当前登录模型额度，它不是普通离线测试。

结果只支持对应的开发阶段决定。真实代码修复、自动触发、长轨迹和新任务迁移需要另外设计对照，并重新跑相应基线。
