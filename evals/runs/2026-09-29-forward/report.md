# 两个组件的契约审查

组件 A 已证实违反“探测不建立会话”的契约；组件 B 在给定的按需缓存契约和本次串行验证范围内未发现违约，不需要修改。判断依据是显式契约与实际状态转换，而不是 lookup/get 的方法名。

## A：返回值正确，但未命中时改变了状态

链路：调用者传入不存在的会话 → `self.rows[session]` → defaultdict 创建空字典 → `.get(key)` 返回 None → 调用者收到未命中结果。

实际运行：`lookup('absent', 'answer')` 返回 None，但 rows 从 `{}` 变为 `{'absent': {}}`。最早偏离契约的位置是外层 defaultdict 的索引操作。返回值满足约定，状态副作用违反“不建立会话”的不变量。若调用者用会话是否存在或会话数量做后续判断，空记录可能干扰判断；这些下游后果是推断，本次未运行真实业务链路，也未测量资源影响。

最小修复只替换查询表达式：

```python
def lookup(self, session, key):
    return self.rows.get(session, {}).get(key)
```

外层 `.get` 在缺失时使用临时空字典，不向 rows 插入记录。保持原有 defaultdict 存储和写入方式。修复实现在 validate.py 的 SessionsFixed 中，未改动其他文件。

验证判据为精确相等，没有容差：修复后连续两次查询不存在的会话均返回 None，存储保持不变；对原实现与修复实现分别预置已有答案，均可读取同一答案对象，查询已有会话的缺失键仍返回 None，存储不变。验证全部通过。

## B：首次查询写入属于契约允许的行为

链路：get(key) → 检查缓存 → 未命中调用纯 loader 并保存结果／命中直接返回已保存结果 → 调用者。

契约明确允许按需写入并要求相同键复用。代码以成员判断区分未缓存和已缓存 None，不因结果是假值就重复加载。验证使用纯计算函数，并用 Mock 记录调用次数：对 a、b、none 三个键首次查询各调用 loader 一次，重复查询未增加调用次数；读取其他键后，a 的已有结果仍可读取。最终 rows 为 `{'a': 'A', 'b': 'B', 'none': None}`，共三次 loader 调用。无需把 get 改成无副作用查询，也没有重新采样的契约，因此不能把复用结果判为采样故障。
