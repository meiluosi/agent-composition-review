# LG #8753 · 共享 cache 后，B 图返回 A 图的结果（ACR008，experimental）

**状态**：experimental（ACR008；exact 设计源，但无独立 exact 命中）
**一句话症状**：两个图各有一个名为 `process` 的节点，用 callable object 实现并共享同一个 `InMemoryCache`；B 图返回 `"from graph A"`，它自己的节点根本没有运行。

规则只能静态判断“cache_policy + callable 身份不可解析 + 共享 cache”；`__dynamic__` namespace 碰撞本身是运行时行为。

## 最小修复

优先使用模块级命名函数；必须用 callable object 时，给 cache 显式稳定的 key/namespace，并且不要跨图共享匿名 namespace：

```python
def process_a(state: S) -> dict:
    return {"out": "from graph A"}

graph.add_node("process", process_a, cache_policy=CachePolicy())
# 或：CachePolicy(key=("graph-a", "process"))
```

## 验证边界

- **experimental**：本案例是 ACR008 的 exact 设计源，但没有被独立验证。第三轮只找到 7 条 cache identity 邻近案例，0 条 exact；构建的 #5980 fixture 扫描结果是 0 条 ACR008 + 1 条 ACR004，只能说明命名函数不误报，不能证明 ACR008 正向有效。
- 规则命中 ≠ 线上一定串结果；真正的证据是 cache key 实现与实际命中记录。
- 仓库只做静态扫描；未在本地复现 `__dynamic__` 碰撞后的返回值。
- 不宣称上游已修复该 namespace 问题。
