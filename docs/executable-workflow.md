# v4：结构 → 测试生成 → 执行验收

v4 是候选运行包；当前默认版本内容没有升级。它保留一个 Skill 入口和按症状读取的参考，把重复的结构与记录检查交给标准库脚本。完整运行约定见 [执行模块](../candidates/v4/agent-composition-review/references/executable-contracts.md)。

```mermaid
flowchart LR
    A[真实接口、业务要求与代码] --> B[动作、状态、依赖及契约]
    B --> C[组合义务与有限输入域展开]
    C --> D[适配器实际执行系统]
    D --> E[原始 payload、状态与动作记录]
    E --> F[验收与证据不足判断]
    F --> G[最小修复]
    G --> D
```

结构模型仍需根据项目建立，不能由目录结构自动产生。模板中的检索链路含 retrieve → normalize → aggregate → conclude；测试域涵盖 Found/Empty/Failed、USD/cents、冷热缓存、重试及采样次数。生成器从声明的五个输入轴展开 48 种组合，然后适配器运行真实 Python 逻辑；外部检索和采样服务是固定替身。

一次动作保留 ID、输入、输出、前后状态、依赖和证据来源。检查器验证声明的字段、契约、允许变化的状态键、动作交接与状态连续性；缺证据时给出 unknown。它不因为出现一个通过的 JSON 格式就宣称根因已证实，也不验证未记录的真实世界状态。

在项目根目录复现，无需登录模型或调用外部服务：

```sh
python3 scripts/replay_contracts.py

python3 scripts/build_skill.py --source candidates/v4/agent-composition-review --output dist/agent-composition-review-v4.zip
```

首条命令默认把完整记录写入忽略提交的 `evals/runs/private/replay-contracts.json`。解压后的运行包可独立运行 validate、plan、generate、check；执行用户自己的系统仍需本地适配器。不要将生产日志中的隐私数据直接提交为评测素材。

## 尚未实现的保证

这是一种有限可执行建模方法，不是自动证明器。检查顺序状态流，尚不支持任意并发偏序、概率独立性证明、任意谓词蕴含求解或全局因果发现。前提、契约和观察范围如果遗漏，绿色结果也可能漏掉真实故障。

范畴论在这里指导如何保留组合关系、状态与必要分量；未将“用了类型和测试”称为构造了完整范畴模型。采样调用身份、实际统计依赖、业务正确性和故障因果是不同要求。组合测试的良好结果还要与正常反例及其他系统上的证据共同解释。

## 概念如何影响本轮决策

| 理论视角 | 本轮具体检查 | 不能由此推出的结论 |
| --- | --- | --- |
| 对象、态射与组合 | 类型化输入输出、动作实例、父事件与字段绑定 | 已证明恒等与结合律 |
| 积与余积 | 来源字段保留；found/empty/failed 分支标签 | 任意 schema 都实现了范畴积或余积 |
| 状态与效应 | before/after、写集合、重试计费 | 未观测数据库、网络及并发效应也正确 |
| 函子式结构映射 | 结构动作与执行事件可对应，交接载荷可比较 | 只检查对象字段就保证所有组合关系保持 |
| 自然性与重构 | 使用相同输入和观察标准验证修复 | 任意旧/新实现及旧/新状态都天然兼容 |
| 复制与随机 | 区分复制一次结果与多次调用；允许复用的正常反例 | 不同调用 ID 自动保证统计独立 |
| 局部与整体 | 租户范围、来源追踪与最终结果一起验收 | 局部都通过就满足所有未声明全局约束 |
| 定量组合 | 调用成本、最小改动数、验收率分开报告 | 有普适误差放大系数或统一架构总分 |

本轮动作结构只是让这些问题有可以落地的检查对象。函数融合、状态适配、并发调度和多智能体胶合仍需项目自己的关系、前提与对照，不能通过补齐一组目录名解决。
