# ACR001 · 子图覆盖父图共享状态

**级别**：high（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 子图单独 invoke 正常，接进父图后报 `InvalidUpdateError: At key 'x': Can receive only one value per step`。
- 父图另一个分支刚写过的字段，被平行执行的子图“改回”旧值。
- 子图内部只写了 `s1`/`s2`，但报错/覆盖的却是 `b` 这类子图从未写过的键。

## 为什么发生

子图用没有 `output_schema` 的 `StateGraph(State)` 构建时，默认把**整份状态**作为输出回传。父图把这份完整快照当作更新补丁；如果子图与父图共享状态键，且父图另有并发分支写同一个键，两笔写入就落在同一个 superstep，触发 `InvalidUpdateError`（或后写覆盖先写）。

问题不在“状态键共享”，而在**子图的输出边界等于整个父图状态**：它把“读到的旧值”也当成了“要提交的新值”。

## 最小修复

```python
from typing import TypedDict
from langgraph.graph import StateGraph

class ParentState(TypedDict):
    a: int
    b: str
    s1: int
    s2: int

class ChildOutput(TypedDict):
    s1: int  # 子图真正负责写的键
    s2: int

# 只收窄输出：子图仍读取父图完整上下文（a、b）
child = StateGraph(ParentState, output_schema=ChildOutput)
```

修复后子图输出从“完整快照”变成“自己负责的补丁”，父图其他分支的 `b` 不再被覆盖；并行关系保持原样。

## 验证

- 同一输入重跑 broken 场景，不再抛 `InvalidUpdateError`。
- 子图仍能读到父图上下文（`a`、`b`）。
- 父图 sibling 分支写入的 `b` 保留在最终状态中。

## 误报边界

- 子图是某个共享键的**唯一写者**，且没有并发分支写同一键：完整回传不会冲突，可不修。
- 父图**刻意**要求子图回传全量状态（例如子图就是状态快照生成器）：应显式合并，不要机械改成 `output_schema`。
- 子图与父图状态键完全不重叠：ACR001 不成立，关注是否有 ACR003 的弱提示即可。
