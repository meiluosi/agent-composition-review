# LG #9276 · resume 后重跑已完成节点（ACR106 正向，本地复现）

**状态**：grounded（ACR106 正向；本地复现公开 issue，非社区附件）
**一句话症状**：`agent` 在第一段运行中已经 `node_end`，resume 后它又出现 `node_start`；被 interrupt 的 `gate` 也重启了，但那是预期行为。

`gate` 在 e4 带 `interrupts`，因此被正确排除，没有 ACR106 finding。其余 finding（ACR103/ACR102 等 experimental）属于该 trace 的附带观察，不是本条故障的主结论。

## 最小修复

- 从 pending writes / 精确 checkpoint 恢复，不要重放整个 superstep。
- 给已完成节点的副作用加幂等键（`run_id + node` 完成标记），让重复执行成为 no-op。
- 恢复后先断言“已完成节点没有被再次调度”，再继续业务动作。

## 验证边界

- **本地复现**：按 issue 的图结构在 langgraph 1.2.14 上重放并采集 trace；不是 reporter 附上的原始 trace。不能声称“社区 trace 已验证”。
- resume 标记是手动插入的：LangGraph 默认 debug 流不产生 `resume`/`replay` 事件。没有标记时 ACR106 看不到，这不等于运行时没有问题。
- 该复现已参与 ACR106 的误报修复（v0.3.1），属于开发集；不能当未见保留集或泛化指标。
- ACR106 检测的是“完成 → resume → 再次启动”的模式，不证明每次重启都会造成业务副作用；需要结合节点实现判断。
