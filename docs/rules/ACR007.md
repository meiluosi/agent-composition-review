# ACR007 · 节点返回了状态 schema 未声明的键

**级别**：medium（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 节点里明明 `return {"answer": ...}`，下游却读不到 `answer`，或者只读到旧值。
- 图能跑，不报错，但“这个字段就是没写进去”。
- 更隐蔽的情况：节点返回的键全都不在 schema 里，LangGraph 报 `InvalidUpdateError: Must write to at least one of ['foo']`。

## 为什么发生

LangGraph 把节点返回的 dict 当作**对声明 state schema 的更新补丁**。schema 里没有的键不会自动扩展状态，而是在节点边界被静默过滤。于是：

- 写进未声明键 → 写入消失，下游看不到；
- 只写了未声明键 → 这个节点对状态“什么都没写”，可能触发 `Must write to at least one of [...]`。

这不是“少写了一个字段”那么简单：它是一个**写入所有权/边界**问题——节点以为自己拥有这个键，实际 schema 没有给它。

## acr 输出示例

```text
$ acr scan app/graph.py
app/graph.py:18: medium ACR007
  Node 'n' returns key(s) 'undeclared_key' that are not declared in state schema 'State'.
  LangGraph filters undeclared keys at the node boundary, so this update is silently dropped...
  evidence:
    - node 'n' registered with add_node at line 18
    - state schema 'State' declared at line 8 with key(s): 'x'
    - node returns undeclared key(s): 'undeclared_key' (return line(s): 14)
  fix: Declare the key in the graph state TypedDict (with a reducer if multiple nodes write it),
       or remove/rename the returned key.
  docs: docs/rules/ACR007.md
```

类节点也支持：`add_node("node_1", node1())` 会分析 `node1.__call__` 的 `return`。

## 最小修复

如果这个键本来就该是状态的一部分：

```python
class State(TypedDict):
    x: int
    answer: str        # 声明它；多个写者时再加 reducer
```

如果它只是节点的局部结果，不应该进入状态：

```python
def node(state: State) -> dict:
    answer = compute(state["x"])
    return {"x": answer["next_x"]}   # 只返回 schema 声明的键
```

需要把结果传给下游时，显式放进声明字段，或用 `Command(update=...)` 前确认目标 schema 接受它。

## 误报边界

- 只检查**静态可见的 dict 字面量**返回；`return state`、`return helper()`、`{**state, ...}` 等无法确定键集的返回不报。
- 状态 schema 不在当前文件、或不是 `TypedDict` 时跳过。
- 子图节点走 ACR001/ACR003 的边界检查，不在这里重复报。
- 如果项目故意用宽松 schema（如 `total=False` 但仍有显式字段），未声明键仍会被过滤；只有真正“动态扩展状态”的封装才不适用。
- 规则命中说明“这里可能丢写”，不是证明线上一定丢；先核对实际 `invoke` 结果和 schema 版本。
