# ACR003 · 子图作为节点未声明输出边界

**级别**：medium（静态检查，构图层；弱于 ACR001）
**命令**：`acr scan <path>`

## 症状

- 子图以 `child.compile()` 直接挂到父图节点上，组合后字段莫名出现、消失或被旧值覆盖。
- 出问题时很难说清：子图到底应该回传哪些字段？
- 单独运行子图完全正常，所以团队先怀疑父图逻辑。

## 为什么发生

编译后的子图默认把子图状态作为输出交回父图。只要没声明 `output_schema`，父图就拿到整份子图状态。如果子图与父图状态定义相同，这看起来“没问题”；一旦两边状态逐渐分叉，输出边界就变成隐式的、无人负责的。

ACR001 检查“已经发生冲突的共享键”；ACR003 更宽：**任何未声明输出边界的子图节点**都值得确认一次，即使当前没报错。

## acr 输出示例

```text
$ acr scan tests/fixtures/acr003_positive.py
acr scan - tests/fixtures/acr003_positive.py
1 file(s) parsed, 0 skipped - 1 finding(s): high 0, medium 1, low 0

  MEDIUM ACR003  Subgraph node has no output_schema
    tests/fixtures/acr003_positive.py:27
    Subgraph node 'child' has no output_schema. The complete child state (keys: child_only) is passed back to the parent instead of a narrow, intentional output.
    evidence:
      - child graph compiled without output_schema at line 24
      - child state keys passed back to the parent: child_only
      - parent node 'child' registered with add_node at line 27
    fix: Pass ``output_schema=...`` to the child ``StateGraph`` constructor (or ``compile(output_schema=...)``) to restrict what the subgraph returns.
    docs: docs/rules/ACR003.md
```

## 最小修复

```python
class ChildOutput(TypedDict):
    s1: int
    s2: int

child = StateGraph(State, output_schema=ChildOutput)
parent.add_node("child", child.compile())
```

如果确实需要全量回传，就把规则降级为“设计如此”，但要补测试：断言哪些键会被子图覆盖、覆盖是否可接受。

## 验证

- 明确列出子图输出的键集合，并与父图期望比对。
- 父图中其他分支写入的字段在组合后仍然存在。
- 若保留全量回传，增加一条测试来锁定哪些字段会被覆盖。

## 误报边界

- 子图与父图状态完全相同、且没有并发写者：全量回传风险低，可只作为提示。
- 子图输出被立即用于整体替换（例如分支工作流中的状态快照）：需要看业务语义，不能一概改成 `output_schema`。
- 子图没有共享任何父图状态键：ACR003 仍可能命中（未声明边界），但优先级应低于共享键冲突。
