# ACR004 · 缓存包裹副作用或丢失采样语义

**级别**：medium（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 加了缓存后，本该多次生成的结果变成同一份；投票、采样、多样性下降。
- 重试或恢复时命中旧缓存，跳过了一次本应发生的外部调用。
- 缓存键看起来包含输入，但换模型、换温度后仍返回旧结果。

## 为什么发生

缓存本身不是问题，**缓存的位置和键**才是。两类常见错位：

1. 带副作用的操作（发消息、扣款、建单）被缓存包裹：缓存命中时副作用没有发生，业务语义被改变。
2. 缓存键只包含“问题文本”，没包含模型、温度、采样序号、prompt 版本；把“复用同一结果”和“重新采样”混成一个入口。

## 最小修复

```python
import hashlib, json

def cache_key(question: str, model: str, temperature: float, sample_idx: int) -> str:
    payload = {"q": question, "model": model,
               "temperature": temperature, "sample_idx": sample_idx}
    return hashlib.sha256(json.dumps(payload, sort_keys=True).encode()).hexdigest()

def draft(state: State) -> dict:
    key = cache_key(state["question"], MODEL, TEMPERATURE, state.get("sample_idx", 0))
    if key not in CACHE:                      # 仅缓存纯生成
        CACHE[key] = llm.invoke(...)
    return {"draft": CACHE[key]}              # 副作用留到缓存之外执行
```

## 验证

- 同一问题、不同 `sample_idx` 会得到不同缓存条目。
- 缓存命中/未命中两条路径都跑测试。
- 副作用在缓存命中时不会被跳过（或按设计明确不执行）。

## 误报边界

- 纯读、确定性计算、显式“同一结果复用”的场景：缓存是正确设计，不应修改。
- 缓存键由框架自动生成且已包含完整输入与参数：scan 的静态推断可能不完整，以实际 key 内容为准。
- 副作用本身幂等且缓存命中代表“已完成”：可能无需拆开，但仍要能说清“命中时副作用是否应发生”。
