# ACR006 · 节点内隐藏状态读写

**级别**：low（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 某个节点执行后状态变了，但父图/调用方看不到是谁改的。
- 同一输入重跑结果不一致，日志里找不到写入来源。
- 回放或恢复时，节点读到的是别的分支中途写下的状态。

## 为什么发生

LangGraph 节点正常通过**返回值**提交状态更新。若节点内部直接调用 `get_state` / `update_state`，状态读写就绕过了图的可见提交路径：

- 读取可能看到“当前还没有合并”的中间状态，行为依赖调度顺序；
- 写入不进入本次节点的返回值，父图与测试难以断言；
- 回放时这类旁路调用不会自动重放，导致结果与线上不一致。

## acr 输出示例

```text
$ acr scan tests/fixtures/acr006_checkpointer.py
acr scan - tests/fixtures/acr006_checkpointer.py
1 file(s) parsed, 0 skipped - 1 finding(s): high 0, medium 0, low 1

  LOW    ACR006  Node reads or writes graph state through the checkpointer
    tests/fixtures/acr006_checkpointer.py:14
    Node 'peek' reads or writes graph state through checkpointer methods (update_state() at line 14, get_state() at line 13) instead of the state channels. Composition analysis and reducers cannot see those writes.
    evidence:
      - node function 'peeking_node' interacts with the checkpointer: update_state() at line 14, get_state() at line 13
      - registered as node 'peek' at line 21
    fix: Pass the relevant state through the graph instead of calling ``get_state``/``update_state`` inside a node; keep checkpoint access outside node execution.
    docs: docs/rules/ACR006.md
```

## 最小修复

```python
def review(state: State) -> dict:
    draft = state["draft"]
    checked = check(draft)
    return {"draft": checked}  # 通过返回值提交，而不是 update_state(...)
```

若读取只是为了诊断，明确标注只读并避免依赖“读取时看到的中间值”；若必须有旁路写入，就把它当作外部副作用处理：记录、加测试、在报告中说明。

## 验证

- 状态变化都能在节点返回值或图输出中找到来源。
- 同一输入重复运行，结果一致（不依赖中途状态）。
- 回放/恢复路径与在线路径得到相同状态。

## 误报边界

- 框架 API 要求先 `get_state` 再恢复检查点（例如断点续跑）：这属于预期用法。
- 只读诊断、日志、指标采集：不构成隐藏写，可忽略。
- 读取的状态只用于生成提示词、且不参与控制流：风险较低，但仍应在报告里说明。
