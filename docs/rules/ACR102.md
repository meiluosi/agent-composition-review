# ACR102 · 同一节点重复执行并重复写

**级别**：medium（轨迹检查；需看是否按设计循环）
**命令**：`acr trace <trace>`

## 症状

- 轨迹中同一个节点出现多次 start/end 事件，每次都写同一个状态键。
- 累加类字段（消息、计数、列表）越来越大，实际业务只应发生一次。
- 修了回边条件后问题消失，但说不清之前为什么多跑。

## 为什么发生

节点重复执行的常见原因：条件回边没有终止、重试落在整个节点上、恢复时从更早的 checkpoint 继续、或并行分支在合并后又触发一次执行。每次执行都提交更新，状态就被重复写入。

## 最小修复

```python
def append_summary(state: State) -> dict:
    if state.get("summary_done"):
        return {}  # 已执行：重复进入不再追加
    return {
        "messages": [*state["messages"], build_summary(state)],
        "summary_done": True,
    }
```

同时检查回边条件：节点重复执行往往不是节点本身的错，而是 loop 的退出条件依赖了被覆盖的状态。

## 验证

- 同一轨迹重放，节点只执行一次（或重复执行不改变最终状态）。
- 循环体节点（如迭代 refine）仍能按设计多次执行，且每次写入语义正确。
- 计数/列表类字段不会随重试增长。

## 误报边界

- 节点按设计位于循环中（refine/重试生成），重复执行是预期行为；关键看重复写入是否有幂等保护。
- 每次执行写入不同键或不同列表元素（追加语义明确）时，不一定构成故障。
- 只出现重复 start 事件但没有实际重复写：可能是流事件的重复投递，以 update 事件为准。
