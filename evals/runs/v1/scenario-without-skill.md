# Agent 工程诊断回答

## C1

原因在 `checkout`：把报价的最小单位整数原样传给接受主单位的 `payment_tool`。12900 分被当成 12900 元，再乘 100，得到 1290000 分；展示端换算正确。

针对本例整数元价格，最小修复是在 `checkout` 校验 `q['amount'] % 100 == 0`，再显式传入 `payment_tool(amount=q['amount'] // 100, currency=q['currency'])`。不可不检查就整除，否则会截掉角分。若需接受非整数元，应先把支付接口金额类型扩展为精确十进制，再精确换算，不能依赖浮点数。

验证：输入原报价，展示仍为 129.00 元，支付入参为 129、CNY，账本新增记录为 12900 分；另测不能整除的金额应在扣款前拒绝，不能静默截断。回归断言账本最小单位金额与报价金额相等。

## C2

`candidate` 的缓存键忽略了 `draw_id`，七次调用复用了同一份最终响应。轨迹明确显示只有一次生成，其余六票是重放；全票通过没有提供七次采样的证据。跨次 `solve` 还会继续返回旧候选，违背每次取七个新生成候选的约定。

最小修复是移除完整响应的 memo 读写，让 `candidate` 每次直接调用 `model.generate`。仅把 `draw_id` 加入当前键仍不够：下次 `solve` 又会使用 0—6，继续重放旧响应。

验证：连续两次处理同一问题，分别产生七次真实生成，共十四次；没有最终响应缓存命中或请求合并，生成记录可逐次追溯。不要要求答案文本必须不同，相同答案可能由真实采样产生。之后用固定题集比较正确率与实际调用成本；现有材料不能断言模型内部推理是否多样。

## C3

不能据此认定 self-consistency 已被破坏，也没有删除全部缓存的依据。此缓存只复用静态前缀计算；记录支持五次均进入生成，排除了完整响应重放及请求合并。不同 generation_id 加真实生成记录说明调用确实发生，但不能单独证明随机采样相互独立。

五个答案都是 B，可能来自答案分布集中，也可能受到共享随机状态影响；单题结果不足以区分。先保留该缓存，补记采样参数、种子及随机状态管理方式，检查是否每次重置成相同随机序列。再在多题、多轮上做开启与关闭前缀缓存的受控对照，保持模型和采样配置一致，比较答案分布、相关性和正确率。只有发现缓存改变采样行为的证据，才针对该机制修复。

## C4

字段和单位一致只保证结果能被正确解释，不能保证资源足够。任意两项需求都是 8，满足两两检查；三项同时需求却是 12，大于总容量 10。合并器漏掉了整个集合的容量校验。各 Agent 如实返回 4 并无错误，调度器拒绝符合约束。

在当前三个候选和既定时段、资源池下，“三个都并行且不超售”不可实现。最小修复是在提交前校验所有同时运行作业的需求总和，并在超过容量时返回明确的不可行结果，不能伪造需求或擅自删作业。

最小验收：4+4+4 必须被合并器拒绝并报告需求 12、容量 10；4+3+3 的合法三作业组合可通过容量检查；保留需求真实性与三作业数量检查。待业务澄清：是否允许少选一个、分批运行，或增加容量？获准后再调整选择或调度策略。

## C5

目前不能归因于摘要丢失；检索漏召回、总结失真、回答阶段误用信息，以及线上线下配置或数据差异都尚未排除。

先收集一个可复现的错误案例：用户原问题、实际答案、期望答案及原文依据；保存该次检索结果及排序、总结输入输出、回答输入输出，并记录模型、提示词、索引和语料版本及关键参数。澄清问题：具体哪句话答错，正确依据在哪里，离线测试是否覆盖同类输入？

沿链定位最早丢失或歪曲事实的位置：证据未进入检索结果，先查检索；证据已检到但摘要遗漏或变义，查总结；摘要保留正确证据而回答出错，查回答阶段。固定同一案例和配置逐段重放，并以原始检索内容替换摘要做对照；改善只说明摘要环节值得追查，还需核实具体事实差异。最后将确认的失败案例加入回归集，再评估线上线下差异。

## C6

直接原因是 `select_plan` 在预算内候选中使用了 `min`，选择最低 quality，方向与目标相反。A、B 都符合预算，90 大于 20，应选 A；执行器只是执行选择结果，没有证据指向接口、缓存或并发问题。

最小修复：将最后一行改为 `return max(eligible, key=lambda p: p['quality'])`，保留预算过滤及空集合返回 `None` 的行为。

验证：原输入、预算 100 时返回 A；预算 75 时返回 B，确保超预算的高质量计划不被选中；预算 70 时仍返回 B，验证包含预算边界；预算 69 时返回 `None`。回归检查：非空结果必须在预算内，且 quality 等于所有预算内候选的最大值。
