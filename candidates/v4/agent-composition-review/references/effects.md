# 运行语义与效应

适用于隐藏状态、重试、并发、取消与反馈。一个便于记录的工程模型是：

```text
Input × State → Result × NewState × EffectLog
Result = Success | Failed | Partial | Waiting
```

这只是建模起点；实际系统可能需要随机分布、非终止、外部并发或不可观察效应。不要声称日志列出了所有真实效应。

## 检查动作

- 查询：是否按契约允许刷新缓存、创建记录或更新访问时间？读写名称本身不是契约。比较前后状态，只把禁止的变化报为问题。
- 超时：区分“执行未开始”“已经成功但响应丢失”“是否执行未知”。未知不能自动重试非幂等操作。
- 重试/恢复：确定重放范围、逻辑操作身份和效果次数。幂等键应覆盖同一逻辑操作；补偿不一定恢复到原状态，也不自动撤销历史影响。
- 并行：检查共享状态和资源所有权。两个只读步骤可能争夺限额；两个不同名字的 Agent 可能写同一对象。
- 取消/反馈：检查已提交效应、未完成操作、迭代终止和累计预算。历史错误可被修复，但重复消耗、外部写入可能仍然存在。

**验证**：在 stub 中制造“已提交、响应丢失”，观察重试效果计数；对共享状态模拟合法交错；分别测试契约允许与禁止的查询副作用。修复不能把全部操作串行化或丢弃已有记录当成默认解法。

依据：[Moggi，计算与 monads](https://doi.org/10.1016/0890-5401(91)90052-4) 为带效应计算的组合提供语义框架。选择具体 Monad、Kleisli 组合或效应组合方式需要额外建模；不能仅凭写出上面的签名就声称满足这些结构。[Myers，Categorical Systems Theory](https://www.davidjaz.com/Papers/DynamicalBook.pdf) 可用于进一步建模与环境交互的开放系统。结合律允许改变括号，不允许任意交换动作。
