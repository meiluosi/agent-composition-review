# LG #6446 · 子图回传完整状态，父图并行写同一个键

**状态**：grounded（ACR001；开发集复扫命中，配套运行示例可在本地跑通）
**一句话症状**：父图 `nodea` 同时扇出到 `nodeb`（写 `b`）和一个未声明 `output_schema` 的子图，子图把整份状态（含旧的 `b`）当补丁回传，运行报 `InvalidUpdateError: At key 'b': Can receive only one value per step`。

以上为输出摘录（部分 `message` 已转述为中文）；完整英文文本与行号以实际运行命令的结果为准。

根因不是“子图读了 `b`”（它计算时确实需要），而是**子图的输出边界默认等于整个父图状态**：它把只读上下文 `b` 也当成要提交的更新。

## 最小修复

```python
class ChildOutput(TypedDict):
    s1: int
    s2: int

child = StateGraph(State, output_schema=ChildOutput)  # 只收窄输出
```

子图仍可读取 `a`/`b`，并行结构不变；修复后同一条 scan 命令返回 `0 finding(s)`。

- `examples/langgraph-subgraph-leak/run.py` 在 langgraph 1.0.3 上真实复现了报错并验证修复，可直接运行；这是运行时证据。

- 不表示上游 issue 已被修复，也不表示所有 `InvalidUpdateError` 都是这一种结构；先看 finding 的 shared key 与 `add_node` 行号。
