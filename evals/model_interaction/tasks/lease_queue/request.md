Maintain the persistent worker queue in `app.py`. Correct any behavior that violates the contract below, preserve behavior that already satisfies it, and leave the module usable by other Python code. You may run and add tests. Only Python 3.12's standard library is available.

Public API:

- `Queue(path)` opens a queue in a local SQLite file. Multiple instances at the same path represent the same queue; separately connected callers may operate on it. Existing data survives reopening.
- `put(job_id, payload)` enqueues a unique ID. The caller supplies a nonempty string ID. Supported payloads are the JSON data model: `None`, booleans, strings, finite integer/float numbers, lists of supported values, and dictionaries with string keys and supported values. Empty and nested containers are supported. The queue saves their value at enqueue time. Other Python types are outside the supported payload domain; inputs that the standard JSON encoder rejects must raise an exception as described below. A duplicate ID raises `ValueError`, including after that ID has been completed. Payloads that cannot be represented by the standard JSON encoder (with nonfinite numbers disallowed) raise `TypeError`, `ValueError`, or `RecursionError` without creating a job or altering existing jobs. This includes inputs beyond the encoder’s supported nesting depth.
- `claim(worker, now, lease_seconds)` returns the oldest enqueued eligible job, or `None`. It returns a dictionary with exactly `payload`, `expires_at`, and `receipt`. The receipt is an opaque dictionary that a caller stores and passes unchanged to `ack`. A job is eligible if it has never been claimed, or if its current lease has expired. A lease expires at `now + lease_seconds`, and is expired at that exact time. Time and duration may be fractional. Completed jobs are never eligible. An unexpired lease prevents another claim, including by the same worker.
- `ack(receipt, now)` returns `True` exactly once when acknowledging the currently active, unexpired claim. It returns `False` for an expired, replaced, or already acknowledged claim, leaving any current claim intact. Workers can reclaim work after expiry using the same worker name. Receipts issued by one queue instance work through another instance at the same path.

The caller supplies `worker` as a nonempty string and `now` as a finite `int` or `float`; calls in a scenario use nondecreasing time. Finite values of `now` and `lease_seconds` have absolute value at most `10**12`; larger finite values are outside this task. Expiry arithmetic follows ordinary Python numeric arithmetic. `lease_seconds` is also supplied as an `int` or `float`, excluding booleans, and must be finite and strictly positive; numeric values violating that requirement make `claim` raise `ValueError` without affecting the queue. Handling of other types for these parameters, invalid IDs, and fabricated or edited receipts is outside this contract. Claiming is atomic across separately connected callers: one eligible job cannot acquire two simultaneously active claims.

Payloads and receipts returned to callers must not alias persisted state or caller-owned input. Mutating a returned payload, or attempting an unsuccessful operation, must not corrupt future deliveries. No real clock, background worker, external service, or network is needed.
