# LG #2336 · 条件自环 retry 与并行分支竞争 `count_b`（ACR010，experimental）

**状态**：experimental（ACR010；设计源/开发集，无独立 exact 样本）
**一句话症状**：`a` 并行扇出到 `b` 和 `c`，`c` 有一条条件边回到自己（retry），`b` 已经推进到 `d`；重叠的 superstep 对无 reducer 的 `count_b` 写入多次，报 `InvalidUpdateError: At key 'count_b': Can receive only one value per step`。

## 最小修复

维护者在 issue 中给出的方向就是加 reducer：

```python
from typing import Annotated
import operator

class State(TypedDict):
    count_b: Annotated[int, operator.add]
    # 其他被自环写入的键同理
```

如果业务语义是“最后一次尝试覆盖前一次”，那就必须禁止并行重叠，或把每次尝试写进 `Annotated[list, operator.add]`，而不是单值键。

## 验证边界

- **experimental**：本案例在第二批被标为预期 ACR002，但 ACR002 只建模“兄弟扇出”，漏掉了 retry 自环；ACR010 是在看到这次 miss 之后设计的，因此 `lg2-2336` 对 ACR010 是**开发集**，不是验证集。
- 第三轮没有找到新的“条件自环 + 非 reducer”exact 样本，明确记 `no_sample_found`；不能用邻近案例冒充验证。
- 仓库只做静态扫描；运行时 `InvalidUpdateError` 来自 issue 文本与维护者描述，未在本仓库重跑。
- ACR010 只报“静态可见的条件自环 + 已声明无 reducer 键”，不保证线上一定冲突；动态路由无法确认时不报。
