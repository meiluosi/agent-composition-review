# Agent 组合诊断

从实际证据判断步骤如何组合。数据类型不仅是字段结构，还包括含义、来源、状态及消费者可以依赖的保证。边界和节点都是候选失效位置；图的位置不能替代因果证据。

## 先确定诊断对象

区分用户要找的对象：首次观测错误、导致最终失败的关键错误、当前未解决的阻塞，或架构风险。它们可能在不同位置。沿用任务明确的定义；定义不清且影响结论时先澄清，或并列说明，不能默默替换问题。

只做日志归因时，使用已有轨迹和要求的输出格式。已有修复授权时继续验证修复；架构审查和重构验证才按相关范围扩大检查。

## 保留一条可追溯的证据链

记录与问题相关的输入、动作、输出和状态；为事实保留事件位置和来源。分清动作发起者、执行者、消息发送者及日志中提到的其他组件，不能把它们自动视为同一责任主体。

对候选问题记录：`最早引入位置 → 传播/重试 → 观察到的结果 → 恢复或残留影响`。后续重复错误不自动成为首次根因；早期错误被修复，也不自动证明它从未影响最终失败。

证据标为已观察、由明确约束推导、或待验证假设。拟执行的代码不等于已执行，执行成功不等于业务正确，缺少末尾日志不等于最后一步已失败。

## 比较能解释失败的候选

从轨迹支持的少量候选开始，包括适用的节点内部错误和交接错误。对每个候选检查：哪条明确要求被违反；违反从哪里引入；是否传播到目标失败；后续是否恢复；哪个观察能反驳它。

用反事实组织验证：若只修改这个动作及其必要后续，目标结果是否有理由改变？没有重放或充分证据时，这只是待验证判断。不要用“这里修一下就能继续”证明它是最早责任点。

有直接失败证据的候选与尚未发生的风险分别报告。已有错误不能因为另一个故事更像架构问题就被丢弃。若材料不能确定唯一归因，保留候选与不确定性；被要求只返回一个位置时，按任务定义选择证据最充分的一项，并说明限制。

## 按症状使用组合检查

- 结构/语义、快照/补丁、空值/失败、状态副作用：读 [边界契约](references/boundary-contracts.md) 的相关小节。
- 路径替换或误差传播、复制与重新采样、多智能体重叠冲突：分别读 [高级组合](references/advanced-composition.md) 的对应小节。没有相应症状时无需加载。
- 需要完整审查或修复验收时，使用 [输出与验证](references/review-output.md)；单个归因不套完整报告。

领域计算或代码逻辑决定正确性时，使用对应的推导、测试或领域工具，并把结论连回原始事件。调用其他 Skill 之前明确它需要的材料、交付的证据及失败状态；子检查给出的猜测不能升级为已证实根因。不默认开启多个 Agent，也不把多份相同来源结论当独立证据。

## 验证与交付

提出能区分剩余候选的最小检查；修复后验证目标结果及相关状态、副作用、不变量，保留真实执行状态。只提供诊断时交付结论、事件证据、机制和未确定部分。

类型兼容是组合分析的入口，不保证语义正确或因果归因正确。范畴论的组合、行为保持、复制与胶合思想用于提出检查条件；只有明确模型及假设时才作数学断言。有限样本与类比都不能冒充证明。
