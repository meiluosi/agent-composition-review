# ACR010 · 条件自环写入非 reducer 键

**级别**：medium（静态检查，构图层）
**命令**：`acr scan <path>`

## 症状

- 节点有一条条件边回到自己（retry / 重入），同时另一个并行分支还在推进。
- 某次重试后报 `InvalidUpdateError: Can receive only one value per step`，或者后一次写入把前一次悄悄覆盖。
- 去掉 retry 条件边后图就正常；但业务上又确实需要重试。

## 为什么发生

自环节点会被重新调度；如果它写的状态键没有 reducer，那么“重试”与“并行分支/下一次重入”可能落在同一个 superstep 里，状态键收到多个值。LangGraph 无法合并，只能报错或按单值语义丢失更新。

这不同于 ACR002 的“同一来源扇出到两个不同节点”：这里写者可能是**同一个节点**，冲突来自时间上的重入与重叠。

## acr 输出示例

```text
$ acr scan app/graph.py
app/graph.py:25: medium ACR010
  Node 'c' has a conditional self-loop and writes non-reducer key(s) 'count_b'.
  A retry/re-entry can overlap with another branch in the same superstep...
  evidence:
    - conditional edge from 'c' back to itself at line 25
    - node 'c' writes non-reducer key(s) 'count_b' (add_node at line 23)
  fix: Give the key a reducer, or guard the self-loop so retries cannot overlap with another writer.
  docs: docs/rules/ACR010.md
```

## 最小修复

给键加一个可交换 reducer：

```python
class State(TypedDict):
    count_b: Annotated[int, operator.add]
```

或者把重试限制为单写者：retry 期间不要同时让并行分支写同一个键，或把每次尝试的结果写进 `Annotated[list, operator.add]` 而不是单值键。

如果这个键本来就是“最后一次尝试覆盖前一次”，需要明确它只在串行重试下成立，并加 guard 禁止并行重叠。

## 误报边界

- 只报**静态可见的条件自环**（`add_conditional_edges` 的 target 包含 source）且写的是**已声明、无 reducer**的键。
- 条件边指向别的节点、没有自环、或用 reducer 的键不报。
- 动态路由（callable 返回运行时决定的目标）无法静态确认自环时不报。
- 规则命中不等于线上一定冲突；先看实际 superstep 与是否有并行分支。

## 相关真实案例
