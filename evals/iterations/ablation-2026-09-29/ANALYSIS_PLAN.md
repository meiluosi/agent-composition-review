# 四组开发消融：运行前冻结方案

8 个已参与设计的任务，每条件每例 3 次，共 96 次新运行；不重用历史回答作为本轮基线。任务和四组来自上一轮已提交的 ITERATION_PLAN。目的为诊断加载材料与入口流程的影响，不作泛化效果声明。

- A 无 Skill；B 旧版全包；C 旧版正文；D v2 候选正文。A/B 对每个任务的提示词哈希必须与首轮一致；所有组共用原来的输入、评分器、taxonomy、schema 和任务目标。正文组不访问链接，属于材料消融，不代表按需加载效果。
- 沿用 gpt-6-astra / high、当前 CLI 版本、每次新进程、临时工作目录、禁用工具和宿主 Skill 发现。三路并发，超时 240 秒。随机种子 20260930 决定交错顺序，不控制模型随机性。模型快照和货币费用不可见。
- 首要指标为位置严格匹配。预先比较 C−B（去除参考包）、D−C（替换入口）、D−A（相对基线）。另列 B−A 作为复测对照。Agent、位置与适用 Agent 联合、Pro 类别准确率为次要描述指标。
- 先按任务平均三次重复。分别报告两个数据集及固定八任务集合的结果；合并结果只描述本次目的性开发集合，不代表自然数据频率。按任务配对 bootstrap 10,000 次、种子 20260930，给出 95% percentile 区间。数据集各仅五/三个任务，区间尤其不稳定；所有任务差相同可能产生退化区间，不能解释为总体确定性。
- 不作多重比较调整，也不依靠显著性宣布胜者；这些对比只用于开发诊断。报告各任务成功次数，不能用均值掩盖已有正确案例的退化。
- 缺失/无效/工具调用违规计失败且保留分母；基础设施故障单列，不作为能力判断。全部记录齐全后才生成成绩，不按中途分数改提示词、样本或选择性重试。
- 资源报告实际输入/输出 token、缓存部分与单次墙钟中位数；output_tokens 不再次加 reasoning token。时间包含启动、网络及并发影响。
- 原始事件和理由留本地，公开逐次结构化预测、分数、成本计数与文件哈希。完整输入、原始标签不重复发布；旧数据可按首轮 restore-inputs 恢复并校验。
- 完成后人工复盘理由中的事件来源、已恢复错误、未执行风险，作为知道组别的定性开发分析；不冒充盲评成绩。争议标签照原样评分，不事后改答案。
- 图表包括固定八任务集合的四组准确率与区间、逐任务成功次数和资源对照。历史 144 次不并入本轮图表。
- v2 不因开发集提升而自动替换主 Skill。若没有收益或出现新的语义退化，继续保留候选状态；若值得保留，再预先确定新任务及预算，做保留集与真实使用方式验证。
