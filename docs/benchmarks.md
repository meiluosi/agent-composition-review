这是按当前 Skill 的用途作出的选择。故障归因基准测“是否找对失败原因”，不能单独证明代码修复、架构质量或生产可靠性；这些仍需现有运行回归和带业务不变量的修复验收。

## 本轮核查记录

### Who&When

[官方仓库](https://github.com/ag2ai/Agents_Failure_Attribution)与数据卡均报告 184 条任务，来自算法生成和人工设计的多智能体系统。127 是项目页报告的系统数量，不是任务数量。官方仓库含归因方法和评测入口。

Hugging Face 元数据返回 revision `59b9fcba1aaed7bbf206b5f4d3c68b8face2f49c`，`gated=false`。包含 Algorithm-Generated 与 Hand-Crafted 两组数据。本轮只核查资料和文件元数据，没有运行全量评测。代码仓库的 MIT 标识不能自动替代数据及其上游任务的使用条款。

### Who&When Pro

[项目页](https://whowhenpro.github.io/)报告 12,326 条轨迹、26 个来源基准，通过在成功轨迹中注入单个错误产生标签。该生成方式有利于明确注入位置，但不等于覆盖自然发生的多重故障。

[数据仓库](https://huggingface.co/datasets/Leoxx/whowhen_pro)元数据返回 revision `0bd196c8a040841c4ae167ab33cc8151de246f1f`，`gated=false`，数据卡标示 CC BY 4.0。当前数据服务返回 text 子集 6,257 行；服务总计显示 10,784 行，且 `partial=true`，因此不能把这个数解释为完整发布规模或断言缺失了某些样本。真正接入时应固定 revision，按实际文件重新计数和去重。

数据卡列出 17 个错误模式，项目页写 18 个；官方链接的 GitHub 评测代码本轮浏览返回 404。因此接入前必须冻结 taxonomy 和评分实现，不能混用不同版本或声称已能原样运行官方 harness。

数据卡说明 task、trajectory、ground_truth、extras 是 JSON 字符串。适配时必须解析后分离输入和标签；task 中也可能有参考答案。image_gui 明确采用从 1 开始的步号，其他子集需分别核对，不能统一猜测。

### AgentRx

官方文章报告 115 条轨迹及三个领域；当前 Hugging Face 数据卡仅列 tau_retail 和 magentic_one 两个领域。访问前不能确认受限文件是否覆盖文章所述全部数据。页面标示 CC BY 4.0，但这不取消下载入口的访问条件。

root_cause、failure_summary、step_reason 等含诊断答案，不能作为待测模型的输入。其“首次不可恢复失败”标签定义也不一定等价于其他数据集的“第一个错误”；应分别评分。

## 建议的首轮实验

1. 先为 Who&When 写一个数据适配器，固定 revision 和文件哈希。用一小组明确标为开发集的案例检查步号、身份、标签分离和评测代码，不先读完全部答案。
2. 在剩余数据中按任务来源、系统和同源轨迹分组形成保留集。若无法识别同源关系，记录限制，不仅按行随机切分。调过规则的案例移入开发集。
3. 在相同模型、上下文预算和工具条件下比较当前 Skill、不加载 Skill、上一版本；输入顺序交错。先少量试跑测量实际成本，再确定全量运行预算。
4. 首先报告责任 Agent 准确率、关键步骤精确准确率、二者联合准确率。步号容差只能作为另列指标；Agent 标签不适用时明确适用分母。Pro 接入后再按冻结 taxonomy 增加错误类型 macro-F1。
5. 报告每类任务的结果、重复运行差异和配对不确定区间，不将同一案例的多次采样视为独立任务。保留原始输出、无效格式和失败运行；无法解析的输出不能静默丢弃。
6. 另设正常轨迹与证据不足场景，检查误报和不确定性表达。仅有失败样本的数据集无法测出“对正常架构过度挑错”。

归因成绩与修复成绩分开：轨迹归因通过后，再从可以重建环境的案例中检验补丁，记录结果、副作用、权限、并发与状态隔离是否保持。日志题没有足够代码时，不能把一段修复建议算作已修复。

## 接入边界

公开仓库先维护来源、固定版本、适配脚本、样本 ID 清单和汇总结果；不要把大体积原始数据、受限数据、API 密钥或答案包直接放进 Skill 运行包。依据数据条款决定可分享的内容。

接入不改变日常 SKILL.md。模型加载 Skill 时不应自动读取基准答案。当前只完成资料核查；没有新增已通过的外部基准成绩，也未调用付费模型。
