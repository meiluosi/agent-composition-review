# ACR105 · 最终状态丢键

**级别**：medium（轨迹检查）
**命令**：`acr trace <trace>`

## 症状

- 中间节点写过某个键，最终 state 里没有它，下游读到空值/默认值。
- 合并多智能体结果后，某些字段“消失”而不是被更新。
- 轨迹看着都执行了，但输出少了字段，且没有报错。

## 为什么发生

常见原因不是“没写”，而是写入被整体替换或没被合并：

- 子图/节点返回完整状态而非补丁，覆盖了父图已有键；
- reducer 缺失或返回了新对象，导致旧键被整体替换；
- 结束节点只提交自己关注的部分，丢掉了上下文；
- 条件分支只走了其中一条，另一条产生的字段没合并。

## acr 输出示例

```text
$ acr trace tests/fixtures/trace_parallel_writes.json
acr trace - tests/fixtures/trace_parallel_writes.json
5 event(s) (unified) - 3 finding(s): high 2, medium 1, low 0

state keys: input=['a', 'b'] final=['a']

  MEDIUM ACR105  Final state is missing keys present in the input
    event seq 1
    Final state is missing 'b', which were present in the input state. A node or subgraph dropped state the caller expected to keep.
    evidence:
      - input state from top-level 'input' has keys: a, b
      - final state from top-level 'final_state' has keys: a
      - keys lost between input and output: 'b'
    fix: Check the final node's output for dropped keys; return a full state update or preserve keys deliberately.
    docs: docs/rules/ACR105.md

（同一条轨迹还会报告 ACR103 与 ACR104。）
```

## 最小修复

```python
def merge_state(state: State) -> dict:
    # 不返回整份新状态；只提交本次变化的键，或显式保留旧键
    return {
        "answer": state["answer"],
        "sources": state.get("sources", []),  # 显式保留，避免被覆盖
    }
```

如果是子图导致的丢键，优先按 [ACR001](ACR001.md) 收窄输出边界；如果是并行合并导致，按 [ACR002](ACR002.md) 补 reducer。

## 验证

- 对比中间事件里的键集合与最终 state，确认每个键的消失都有解释。
- 补一条测试：断言关键键在最终输出中存在且非默认值。
- 合并路径（多分支/子图）分别覆盖。

## 误报边界

- 键本来就是临时字段，按设计在结束前删除：不算丢字段，但要在代码/报告里写明。
- 键被重命名或嵌套到别的字段下：先确认数据是否真的丢失，不要只看顶层 key。
- trace 截断或采样导致中间事件缺失：以完整轨迹或补充日志为准。
