# ACR103 · 同一步并行写同一键

**级别**：high（轨迹检查）
**命令**：`acr trace <trace>`

## 症状

- 轨迹里同一个 superstep 有两个节点写同一个状态键。
- 运行有时报 `InvalidUpdateError`，有时能跑完但结果不稳定。
- 静态 scan 没报，因为两个写者来自动态分支/子图。

## 为什么发生

并行节点在同一 superstep 提交更新，框架要求每个键只有一次写入（除非有 reducer）。如果两个分支都写同一个单值键，运行结果要么直接失败，要么取决于谁先完成——这是一条**数据竞争**，不是“偶发 bug”。

## 最小修复

```python
from typing import Annotated

def merge_draft(left: str, right: str) -> str:
    # 若业务允许多版本，合并为列表；若必须唯一，改为单一写者
    return left if len(left) >= len(right) else right  # 仅示例，需业务确认

class State(TypedDict):
    draft: Annotated[list[str], operator.add]
```

多数情况下更正确的是**收敛写者**：并行分支各自写自己的键，最后由一个节点合并，而不是给共享单值键加“挑一个”的 reducer。

## 验证

- 同一轨迹重放不再报并发写错误。
- 交换并行完成顺序，最终状态不变。
- 恢复/重试不会因 reducer 重复执行产生重复内容。

## 误报边界

- 两个写的是不同键：不是 ACR103。
- 键已有 reducer 且轨迹显示合并正确：应降级为通过。
- 两个分支虽然并行，但其中一个在条件边上被跳过：实际只有一个写者，不构成冲突。
